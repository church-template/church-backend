📝 현재 문제점
---

- 교회 홈페이지의 부서(미션팀) 페이지 사진은 프론트 코드에 정적 파일로 들어 있어서, 사진을 바꿀 때마다 개발자가 코드를 고쳐 배포해야 한다.
- 부서 사진은 교인이 나이를 먹거나 교회를 떠날 때, 행사가 있을 때마다 바뀐다. 떠난 분이 사진을 내려 달라고 하면 바로 빼야 하는데, 지금은 개발자를 거쳐야 해서 그동안 계속 공개된다.
- 부서(`Department`)에는 이름, 설명, 담당자, 상위 부서, 정렬 순서만 있고 사진을 연결할 칸이 없다.
- 갤러리 앨범은 `/api/gallery/**` 경로라 `GALLERY_VIEW`(교인) 전용이다. 그래서 공개 부서 페이지가 앨범을 직접 읽을 수 없다.
- `GET /api/media/{id}` 응답에 `Cache-Control`이 없어서, 공개 페이지에서 사진을 볼 때마다 백엔드가 파일을 다시 보낸다. 여러 교회가 함께 쓰는 서버라 사진을 공개 페이지에 옮기면 이 부하가 커진다.

🛠️ 해결 방안 / 제안 기능
---

- 부서에 **비워도 되는 칸 2개**를 추가한다. 기존 칸은 바꾸지 않아서, 이 칸을 쓰지 않는 교회 프론트는 수정 없이 그대로 동작한다.
  - `heroMediaId`: 대표 사진(미디어 라이브러리의 이미지 1장). 부서 목록 카드와 상세 상단 히어로에 쓴다.
  - `albumId`: 활동 사진 앨범(기존 갤러리 앨범 재사용).
- 공개 부서 조회가 연결된 앨범의 사진 id 목록을 **앨범 순서대로** 함께 돌려준다. 앨범 경로(`/api/gallery/**`)의 회원 전용 규칙은 그대로 둔다. 관리자가 연결한 앨범의 사진만 부서 응답을 통해 공개된다.
- `GET /api/media/{id}`에 `Cache-Control`을 붙인다.

⚙️ 작업 내용
---

- [ ] DB: `department` 테이블에 `hero_media_id`, `album_id` 컬럼 추가(둘 다 nullable)
- [ ] 생성, 수정(PUT), 부분 수정(PATCH) 요청에 두 칸 추가(선택)
- [ ] **PUT 호환 확인**: 새 칸을 보내지 않는 기존 프론트가 PUT으로 부서를 수정해도 두 칸이 지워지지 않아야 한다. 아니면 각 교회 프론트를 먼저 고쳐야 한다. 둘 중 무엇으로 할지 정하고 api-docs에 적는다.
- [ ] 공개 응답
  - `GET /api/departments`: 각 부서에 `heroMediaId`
  - `GET /api/departments/{id}`: `heroMediaId`, `albumId`, `photos`(연결된 앨범 사진의 mediaId 목록, 앨범 순서)
- [ ] 검증: `heroMediaId`는 이미지 미디어만, `albumId`는 존재하는 앨범만(아니면 400)
- [ ] 미디어 참조(`/api/admin/media/{id}/references`)에 부서 대표 사진 포함 → 부서에서 쓰는 사진을 지우려 하면 어디서 쓰는지 보이게
- [ ] 연결된 앨범이 삭제되면 부서의 `albumId`를 비우거나, 삭제를 막는다(둘 중 정함)
- [ ] `GET /api/media/{id}`에 `Cache-Control` 추가
  - 제안: `public, max-age=86400`(1일)
  - 미디어 id 내용은 바뀌지 않으므로 더 길게 잡아도 되지만, 떠난 분 사진을 지운 뒤에도 방문자 브라우저에 그 기간만큼 남는다. 그래서 1일을 제안한다.
- [ ] `docs` OpenAPI 갱신 → 각 교회 프론트의 `client/docs/api-docs.json` 사본 갱신 안내
- [ ] 테스트: 새 칸 없이 PUT해도 기존 값 유지, 공개 응답의 photos 순서, 회원 전용 앨범 경로 규칙 유지, 미디어 응답 헤더

범위 밖
---

- 세대 라벨, 한 줄 요약, 대상, 초대 문구 같은 짧은 글은 이번에 칸을 만들지 않는다. 거의 바뀌지 않아서 각 교회 프론트 상수에 둔다.
- 부서별 담당 권한(예: 한 팀 담당자는 그 팀만 수정)은 하지 않는다. 기존 `DEPT_WRITE` 하나로 모든 부서를 수정한다.
